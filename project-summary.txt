1. DESCRIPTION DU PROJET
────────────────────────────────────────────────────────────────────────────────

Nom              : BuySellSeychelles
URL              : https://buysellseychelles.com
Concept          : Marketplace de petites annonces en ligne style Leboncoin,
                   dédiée au marché des îles Seychelles.
Public cible     : Résidents et expatriés des îles Seychelles (Mahé, Praslin,
                   La Digue, Silhouette, autres îles).
Marché           : Seychelles — monnaie principale SCR (Seychellois Rupee),
                   EUR accepté pour l'immobilier, bateaux et tourisme.
Langues          : Anglais (langue principale) + Créole seychellois / Seselwa
                   (toggle 🇸🇨 Kreol dans le header).
Objectif         : Plateforme locale gratuite, simple, mobile-first permettant
                   d'acheter et vendre n'importe quoi aux Seychelles sans
                   commission ni intermédiaire.

2. STACK TECHNIQUE
────────────────────────────────────────────────────────────────────────────────

FRONTEND
  - Framework    : Next.js 16.2.6 (App Router, Server Components + Client Components)
  - Langage      : TypeScript 5.7.3
  - UI           : React 19, Tailwind CSS 4, Radix UI (primitives headless)
  - Icônes       : Lucide React
  - Carousel     : Embla Carousel
  - Cartes       : Leaflet + React-Leaflet (OpenStreetMap)
  - Formulaires  : React Hook Form + Zod
  - Graphiques   : Recharts
  - State global : Zustand
  - Fetch/cache  : SWR

BACKEND / API
  - Routes API   : Next.js App Router API Routes (/app/api/**)
  - Auth         : Supabase Auth (email/password + OAuth Google, magic link)
  - Base données : Supabase (PostgreSQL), RLS (Row Level Security) activé
  - Storage      : Supabase Storage (bucket "listings" pour photos annonces,
                   bucket "Avatars" pour avatars profil)
  - Realtime     : Supabase Realtime (messages, notifications en temps réel)

SERVICES TIERS
  - Hébergement  : Vercel (déploiement automatique, edge network)
  - Email        : Resend (noreply@buysellseychelles.com) — emails transactionnels
                   (confirmation inscription, messages, alertes, notifications prix)
  - Analytics    : Google Analytics 4 (ID: G-CZ9881KKHG)
  - Monitoring   : Sentry (@sentry/nextjs) — suivi des erreurs en production
  - Paiements    : Stripe (installé, intégration PRO/boost fonctionnelle côté code)
  - Anti-spam    : Google reCAPTCHA v2 sur le formulaire de contact
  - Push notifs  : Web Push VAPID (web-push library) — notifications navigateur
  - Maps         : OpenStreetMap + Leaflet (geocodage Seychelles pré-défini)
  - PWA          : manifest.json + service worker manuel (public/sw.js, network-first)
                   enregistré dans app/layout.tsx — pas de dépendance next-pwa

INFRA / DEVOPS
  - CI/CD        : Vercel CLI (déploiement : NODE_TLS_REJECT_UNAUTHORIZED=0 npx vercel --prod)
  - DNS / Domaine: buysellseychelles.com configuré sur Vercel
  - DMARC/DKIM   : Enregistrement _dmarc TXT configuré pour Resend
  - Environnement: Variables Vercel (SUPABASE_SERVICE_ROLE_KEY, RESEND_API_KEY,
                   NEXT_PUBLIC_SUPABASE_*, RECAPTCHA_SECRET_KEY, VAPID_*, STRIPE_*)

VÉRIFICATION D'IDENTITÉ (Identity Verification) — PROCESSUS COMPLET
  Workflow complet de bout en bout (soumission → décision admin → notification
  vendeur), fonctionnel et en production.
  ✓ Soumission : depuis le bandeau /dashboard, le vendeur upload une photo de sa
    pièce (CNI ou passeport). Le document est stocké, le statut passe à "pending".
  ✓ Email admin → buysellseychelles@gmail.com à chaque soumission, contenant :
    aperçu du document + lien "View document", et DEUX boutons
    d'action en un clic : "✓ Confirm ID" et "✗ Reject ID".
  ✓ Chaque bouton ouvre une PAGE INTERMÉDIAIRE SÉCURISÉE (admin uniquement) :
    - URLs /verify-id/confirm et /verify-id/reject, protégées par un token HMAC
      signé (verificationId + userId, non rejouable/forgeable) ET la nécessité
      d'être connecté en tant qu'administrateur (sinon écran "Admins only" 401).
  ✓ "Confirm ID" : la page affiche le document, puis confirmation → active le badge
    "🪪 ID Verified" sur le profil /seller ET directement sur la page annonce
    (profiles.id_verified = true) + email automatique au vendeur confirmant
    l'acceptation ("Your identity has been verified").
  ✓ "Reject ID" : la page intermédiaire propose le choix du/des motif(s) (cases) :
    Document unreadable (illisible), Wrong type of ID (mauvaise pièce),
    Document expired (expirée), Poor photo quality (mauvaise qualité), Other (autre,
    avec note libre obligatoire) → email automatique au vendeur avec le(s) motif(s)
    et l'invitation à re-soumettre un nouveau document.
  ✓ 4 ÉTATS PERSISTANTS en base (table identity_verifications, statut par user) :
    none (non soumis) · pending (en attente) · approved (accepté) · rejected (refusé).
  ✓ Bandeau /dashboard adaptatif selon l'état :
    - none / rejected → formulaire d'upload ("📤 Upload ID document")
    - pending        → "Under review" (badge jaune), 24–48 h, AUCUN bouton
    - approved       → "ID Accepted" (encart vert permanent, plus de formulaire)
  ✓ Décision partagée (applyVerificationDecision) par le panneau admin
    /admin/verifications ET les liens email → les deux restent synchronisés.
  ✓ Email reçu en un seul exemplaire : double envoi corrigé (garde anti
    double-soumission côté client + lecture du statut via service-role pour éviter
    que le bandeau ne se réinitialise à chaque rechargement et relance l'envoi).

8. STRUCTURE DES ROUTES API

ANNONCES
  POST   /api/listings/delete        Supprimer une annonce + photos
  POST   /api/listings/renew         Renouveler une annonce (60 jours)

NOTIFICATIONS
  POST   /api/notify/alerts          Alertes de recherche (nouvelle annonce)
  POST   /api/notify/listing-update  Annonce modifiée (favoris)
  POST   /api/notify/message         Nouveau message reçu
  POST   /api/notify/new-listing     Nouvelle annonce (abonnés vendeur)
  POST   /api/notify/price-drop      Changement de prix (favoris)
  POST   /api/notify/transaction     Vente confirmée (évaluation mutuelle)

PUSH
  POST   /api/push/subscribe         Enregistrer abonnement push VAPID
  POST   /api/push/new-listing       Push : nouvelle annonce (abonnés)

VENDEUR
  GET/POST /api/seller/follow        Vérifier/toggle suivi vendeur
  GET    /api/seller/response-stats  Taux de réponse vendeur

ALERTES
  GET/POST/DELETE /api/alerts        CRUD alertes de recherche

AVIS
  POST   /api/reviews                Publier un avis

SIGNALEMENTS
  POST   /api/report                 Signaler annonce / utilisateur

CONTACT
  POST   /api/contact                Formulaire de contact (reCAPTCHA + rate limit)

STORAGE
  POST   /api/storage/upload         Upload image (check 5 MB)

STRIPE
  POST   /api/stripe/checkout        Créer session de paiement
  POST   /api/stripe/webhook         Recevoir événements Stripe
  POST   /api/stripe/boost           Booster une annonce
  POST   /api/stripe/subscription    Abonnement PRO

IA (OpenAI)
  POST   /api/ai/optimize            Optimiser le titre d'une annonce
  POST   /api/ai/price-suggest       Suggérer un prix
  POST   /api/ai/quality             Score qualité d'une annonce

TRACKING
  POST   /api/track/view             Incrémenter les vues
  POST   /api/track/click            Incrémenter les clics contact
  POST   /api/track/listing          Tracking listing

ADMIN
  POST   /api/admin/delete-listing   Supprimer annonce (admin)
  POST   /api/admin/resolve-report   Résoudre signalement
  POST   /api/admin/verify           Vérifier identité utilisateur

CRONS (déclenchés par Vercel Cron)
  GET    /api/cron/expire-listings   Expirer les annonces + photos orphelines
  GET    /api/cron/rank              Recalculer le ranking
  GET    /api/cron/recompute-ranking Recompute ranking complet
  GET    /api/cron/boost-*           Gestion boosts (expire, pulse, cleanup…)

VUES
  POST   /api/views/increment        Incrémenter compteur vues annonce

AUTH
  POST   /api/auth/welcome           Email de bienvenue après inscription

IDENTITÉ
  POST   /api/verify-identity        Vérification KYC utilisateur

DISPUTE
  POST   /api/dispute                Signalement de litige
